# Changelog

Current release history for the v1.27 series. See the [Changelog Archive](docs/CHANGELOG-ARCHIVE.md) for v1.26.x and earlier release notes.

### [v1.27.10] - In Development

- **Editor Toolbar Colours**: Light mode uses a pale-grey toolbar with charcoal controls, while dark mode retains the dark-grey palette with shared lime accents. Toolbar top corners follow the editor frame in both modes. Existing button shapes, sizes, order, menus, responsive wrapping and sticky behavior remain unchanged, as do the writing canvas and light/dark dialogs.
- **Editor Maintenance**: Separated styling, controlled Insert and Media Library dialogs, and image/video/table tool views into focused components. Editor state, validation, selection restoration, undo history, media requests, content synchronization and save behavior remain owned by the main editor, with no layout or feature change.
- **Internal Core Modules**: Moved installer setup-key ownership, content-view deduplication, rate limiting and response helpers into protected core/ modules. The existing security.php entry point, session/CSRF startup order, setup-key and quota storage locations remain unchanged. Apache install/repair templates and Nginx guidance deny direct access to the internal namespace. Integrity Check detects a missing core shield and Repair restores it, including after an OTA update that preserves existing .htaccess files; no database migration is required.
- **Category Path Advisory**: The post editor warns when a category's URL segment matches a VonCMS folder, such as core or data. This helps avoid collisions with Category & Name permalinks without blocking saves, renaming categories or weakening protected-folder rules. Existing colliding URLs still require a different category name or Post Name permalinks.
- **Lean Public Plugin Settings**: Initial HTML settings and the guest settings API now include only effectively active system-plugin configuration and enabled custom HTML plugins. Disabled configurations remain stored and available to authorized admins for reactivation. Active plugin IDs and status are projected together so removing unused data cannot activate an inactive plugin. Discussion OFF, empty widget/navigation lists, and meaningful `false`, `0`, and empty values remain unchanged; no database migration or authentication change is required.
- **Dependency Maintenance**: Updated the complete direct TipTap package family from `3.31.4` to `3.32.0`, Lucide React from `1.56.0` to `1.57.0`, and React, React DOM and React Is together from `19.3.0` to `19.3.1` within their compatible ranges.
- **Admin Settings Readiness**: Admin settings screens wait for complete authorized settings before allowing edits, preventing SPA navigation from overwriting saved inactive plugin configuration. Failed or expired-session reads now offer retry, and outdated public drafts are rejected. Existing roles, server permissions and discussion OFF behavior are preserved.
- **Official OTA Trust Boundary**: Updates now require the official VonCMS Deploy asset, matching server-fetched GitHub release metadata and its checksum. Caller-supplied hashes cannot authorize another package; official tag aliases, listed checksum sidecars, validated CDN redirects and rollback remain supported.
- **Login Attempt Isolation**: Successful login refunds only its own reserved IP attempt rather than clearing other failures. Known accounts share a bounded 15-minute quota across username/email aliases and client addresses, with a separate ledger from password recovery. IPv6 privacy addresses share a /64 login budget; client-supplied forwarding headers remain untrusted.
- **Targeted Feed, Import and Login Hardening**: RSS validates decoded link and media URLs using the shared public URL policies, removes active SVG/MathML and responsive URL-list attributes, and preserves ordinary links, images and embed links across root/subfolder installs. WordPress media imports reject non-global destinations and private-address aliases in translated or mapped IPv6 forms while retaining DNS pinning and per-hop redirect checks. Login checks normalize native bcrypt work across legacy and current PHP hash costs without changing stored passwords or quota policy. Comment submissions reserve their quota atomically before validation so concurrent requests cannot exceed the remaining allowance.
- **Read-Only Database Inspection and Trusted Restore**: Database inspection rejects execution-capable EXPLAIN ANALYZE and uses a database-enforced read-only transaction. SQL restore rejects executable comments, query-backed table creation and expression-based INSERT values, while preserving VonCMS backup literals, long article bodies and destructive-restore confirmation. Connections using NO_BACKSLASH_ESCAPES or ANSI_QUOTES are refused before backup or import because their quote rules disagree with the backup parser; connection settings and existing data are not changed. The import screen clarifies that only trusted personal backups should be restored.
- **Text and Embed Boundaries**: Article/page titles in content management, navigation selection, profiles and sidebar lists now render as text. Public content removes form controls, unsupported iframe providers, imported stylesheet tags and application CSS classes while preserving supported video embeds, safe inline formatting, fragment anchors and link relationships. Primary Admin custom plugins retain their explicit CSS capability without enabling forms or arbitrary iframes. Explicit ad content retains its separate opaque-origin sandbox, including form snippets.
- **Private Settings Mirror**: The next successful Settings save rebuilds the compatibility mirror and staging files with private filesystem permissions, omits unused AI/IndexNow credentials and no longer falls back to a non-atomic copy. Legacy SMTP fallback remains available in the protected mirror; filesystem shields and correct hosting configuration remain required.
- **Mail and Media Compatibility**: SMTP and PHP mail use folded MIME headers, normalized line endings and base64 HTML bodies. GIF originals retain their animation; JPEG EXIF orientation is applied before resizing, with original-file fallback when EXIF support is unavailable. Disabled optimization and original-file fallbacks may retain metadata.
- **Entry and Hosting Hardening**: Boot base paths are serialized as JSON, session-binding failures return HTTP 401, and the Nginx helper-deny example now includes the already self-protected view helper.
- **Gemini Request and WordPress Import Hygiene**: Gemini requests send their API key in the supported authentication header instead of the URL, including model fallback requests. New WordPress post/page imports remove scripts, stylesheet tags, form controls, event handlers and unsafe URL attributes before storage while retaining ordinary rich content and supported embeds. Untrusted responsive URL lists are omitted; existing saved articles, permissions and database structure are unchanged.

Original HTML extraction, spacing, Unicode-aware limits, and word-safe truncation remain unchanged.
- **Maintenance Baseline**: Aligned package metadata and current documentation with v1.27.8. Installer, bundled themes, and built-in plugins retain their compatible v1.27 major-series identity; no new feature or database migration is introduced.
