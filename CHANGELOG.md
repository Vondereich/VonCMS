# Changelog

Changes and release history for the v1.28 and v1.27 series. Dated entries identify release packages; download availability is listed on [GitHub Releases](https://github.com/Vondereich/VonCMS/releases). Historical entries retain their original status and dates. See the [Changelog Archive](docs/CHANGELOG-ARCHIVE.md) for v1.26.x and earlier release notes.

### [v1.28.3] - In development

- **TechPress Mobile Latest Updates**: Uses compact rows below the existing 640px breakpoint, with the headline on the left and a 16:9 thumbnail on the right. Headlines retain their full text but display at most three lines; dates remain visible and author details return on larger screens. Hero, Latest Highlights, tablet/desktop layouts, theme colours and discovery queries are unchanged.

- **Digest Footer Contrast**: Uses the theme's warmer grey alternate surface in light mode and its existing dark alternate surface in dark mode. Footer descriptions, RSS and copyright use the existing secondary text colour for legibility. Content cards, saved accents, newsletter controls and footer links are unchanged.

- **Slug Routing**: Fixed slug routing boundaries.

- **Personal AI Keys**:
  - **Private access**: Primary Admin (Root or Admin ID 1), appointed Admin, Moderator and Writer can save an encrypted Gemini key in their own User Manager editor. Writer/Moderator receive a self-only view, not user-management permission. Admin management never exposes another user's key or key status. Save/Replace and Remove use session-owned targets, CSRF and stale-revision rejection.
  - **Key selection**: AI Generate/Check select the personal key first; only its absence permits shared access. Expired, damaged or rejected personal keys never silently retry with the shared paid key.
  - **Model guidance**: A theme-aware information panel groups the privacy and model guidance; expiry guidance stays beside its control. The editor currently follows the Primary Admin's model setting. Additional AI choices are described as future plans, not available controls; key selection and billing behavior are unchanged.
  - **Expiry and storage**: Optional local 30-day expiry starts on Save/Replace. Personal keys are not persisted in browser storage, public profiles or settings.
  - **Upgrade and rollback**: Existing installations require Primary Admin Database Repair to create `user_ai_keys` and the private API-settings lock anchor; fresh installs create both automatically. A files-only rollback to older code ignores personal keys and may resume shared paid-key access. Review that access before rolling back.

- **Database Repair Notification**: The Primary Admin's database check includes personal AI key storage, so missing or incomplete structures trigger the existing bell warning. The README also explains how to open Repair directly when no notification is visible. Repair permissions and shared/personal key selection are unchanged.

- **Multi-Key Encryption Rotation**: Requires an encrypted shared key; personal-only installations do not currently offer rotation. Primary Admin rotation re-encrypts the shared key and all saved personal keys, preserving provider values and expiry, including keys retained for demoted accounts. Short database locks coordinate saves, reads and rotation. Failed transitions retain recoverable key generations without unbounded history. Missing master material is not regenerated while encrypted records remain; restore its matching private backup.

- **Security Source Card**: Long IPv6 source addresses wrap inside the Security Dashboard card without changing collected events or source handling.

- **Content Manager Responsive Actions**: Posts/Pages use their existing cards until the available content area can fit the table, keeping Edit/Delete within view on tablets and when the sidebar is open. The Page navigation toggle spans its card action group with clear Add to Nav/Remove Nav labels. Existing callbacks, permissions, publication fields and queries are unchanged.

- **Theme Startup Canvas**: Theme-owned `theme.json` metadata supplies validated startup colours through the shared PHP render helper and Source build. Public Prism pages use their fixed dark canvas before React renders, including after another theme used light mode. Global entries contain no theme-specific exceptions. Missing or invalid startup metadata uses the ordinary canvas; saved light/dark preferences, private entries and other themes remain unchanged. Startup markers and colours are cleared when leaving the public site.

- **Discovery Footer Stability**: Default, Prism, TechPress and Digest reserve a viewport of space while their Home/category discovery area has no articles to display. This prevents the footer flashing into view when returning from a directly opened Post/Page before the Home list arrives, including the first render before the request starts. The reservation is removed when articles are available; empty/error messages remain usable. Portfolio, Corporate Pro, request/query behavior, stored settings and login feedback are unchanged.

- **Public Login Feedback**: Successful public popup sign-in updates the signed-in user immediately, fades the existing modal out over approximately 180 ms and shows a theme-aware confirmation at the top right for two seconds, matching other notifications. Respects reduced motion and keyboard focus without drawing an outline around the content/hero; interactive control focus indicators are retained. Cleans up pending dismissal work when the modal closes or the route changes. Failed login and email-verification responses do not show success. The login design, standalone `/login` redirects, admin reauthentication, CSRF, remember-me and PHP session behavior are unchanged.

- **Public Name And Title Encoding**:
  - **Consistent text**: Resolves one legacy entity layer in site names across server metadata, initial/public settings and RSS, retaining the "My Website" fallback. Post/Page metadata and RSS titles match theme headings; final HTML labels are escaped, and resolved content/collection schema titles are not decoded again. RSS descriptions reuse plain-text SEO cleanup.
  - **Unchanged boundaries**: Stored content/settings, authorization, URLs and database schema are unchanged. This does not force Google's selected site name or search appearance.

- **First-Publication Clock Consistency**: New first-publication timestamps from Save Post/Page use the configured CMS timezone, matching scheduling and News Sitemap comparisons even when MySQL uses a different timezone. Existing publication/creation timestamps and date-based URLs are not rewritten; ambiguous historical timestamps are not automatically repaired. No schema or server-timezone change is required.

- **News Publication Readiness**: News queries require the existing publication capability activated by installation or successful Database Repair. Upgraded/restored sites without that readiness return HTTP 503 with Repair guidance instead of using database-clock creation dates in a successful but incomplete feed. The ordinary sitemap index remains available and omits unavailable News links; disabled feeds still return 404. Repair restores eligibility for new CMS-timestamped publications without reinterpreting pre-Repair dates. No automatic schema migration, new table or change to ordinary public/RSS date fallbacks is introduced.

- **Date Permalink Guidance**: The Date & Name preview includes year, month and day and correctly describes its original creation-date basis. Actual URL generation is unchanged.

- **Dependency Maintenance**: Updates OpenRouter SDK from 1.5.81 to 1.5.103, the TipTap family from 3.33.1 to 3.34.0, Lucide React from 1.71.0 to 1.73.0, Prettier from 3.9.10 to 3.10.1, Vite from 8.3.7 to 8.3.8, PostCSS from 8.5.32 to 8.5.33 and development-only ESLint from 10.14.0 to 10.15.0 within their compatible ranges. PHP requirements remain unchanged.

- **Reviewed Install Scripts**: Explicitly denies the OpenRouter SDK's optional development-only model-type check, resolving npm's unreviewed-script warning without blanket script approval. Runtime behavior and dependency versions are unchanged.

- **Version Baseline**: CMS package, lockfile, OTA metadata and current documentation use 1.28.3. Installer, bundled theme and built-in plugin labels remain 1.28. This development entry is not a published release.

### [v1.28.1] - 2026-11-06

- **Delegated Authorization Corrections**: Comment status changes and deletion of another user's comments require the shared reviewer-only moderation capability instead of general staff access. Member/Writer deletion of their own comments and existing staff read visibility are retained. Appointed Admin Settings saves cannot change the Primary Admin's IndexNow enable switch, including direct or legacy settings requests; delegated ordinary settings and Primary Admin controls remain available. No database migration or central session-policy change is introduced.

- **Opt-in News Sitemap**: VonSEO Advanced settings can enable `/sitemap-news.xml`, inherit the site's publication name/language or override them, and include all or selected news categories. Language inheritance uses the shared schema helper, taking the first code from a comma-separated General setting while retaining regional and Chinese normalization; the saved General value and article schema type are unchanged. Only published articles from the preceding 48 hours are listed, using the original publication timestamp with the shared scheduled/creation-time fallback, never the edit date. Eligible results are split into at most 1,000 articles per file and linked from the ordinary sitemap index. Empty recent windows stay empty; disabled feeds return 404 and unavailable publication metadata returns 503 without taking the ordinary index offline. Existing permalink/base paths, ordinary sitemap, RSS and llms.txt remain separate. No image-width restriction, database migration or Google News inclusion guarantee is introduced.

- **SQL Import Parser Clarity**: Uses one explicit cursor while scanning quoted SQL values, avoiding a nested loop-variable diagnostic without changing restore validation or accepted statements.

- **Protected Post Read Validation**: Single-post and post-list reads derive protected-content permissions only from a successfully revalidated session. A temporary identity-query failure no longer lets retained staff roles expose drafts, protected listings or counts. Public reads, forced-public listings and valid staff access are retained; central session recovery policy and database schema are unchanged.

- **Upload Fixture Isolation**: Disposable PHP CGI upload tests disable OPCache for their own child processes so failure-injection checks execute the current copied image processor rather than cached code. Production uploads and hosting OPCache configuration are unchanged.

- **Post/Page Deletion Preview**: Single and bulk Delete actions show the selected titles, IDs, status and available summaries before permanent deletion. Cancel, Escape and backdrop dismissal send no deletion request. Confirmation waits for the actual server result, prevents duplicate clicks and retains unconfirmed items after a partial failure; leaving the manager stops later bulk requests without redirecting a new preview. Per-collection refresh survives route-wrapper replacement so returning before a successful deletion response does not leave the deleted row visible. Mounted single/bulk operations share one refresh after settling, including partial success; removing the last row on a later page refreshes the preceding page without a redundant out-of-range request. Existing delete endpoints, server permissions and media files are unchanged. This is a confirmation preview, not Trash, Restore or Undo; no database migration is introduced.

- **Known Automation Measurement Exclusion**: Tracking POSTs and the shared visitor service exclude declared crawlers and recognized automation from new visitor, lifetime content-view and daily article-view measurements without denying public content. Crawler-rendered HTML carries a document-only exclusion marker so the bundled frontend does not send native tracking when its renderer changes User-Agent. Bot-name matching uses recognized crawler products rather than arbitrary device-name suffixes, retaining CUBOT phone visits. Ordinary Linux/mobile browsers, consent, collection modes and deduplication are retained; no IP ban, historical rewrite or database migration is introduced. This is best-effort measurement hygiene, not proof of human visitors or detection of undisclosed automation.

- **Route-scoped Theme Discovery**: Prism, Digest, TechPress and Corporate Pro request the homepage/category article list only while a discovery view is active. Article, Page and profile views retain their own content, Related Posts and widget flows without the unused listing request. Existing shared query cancellation, search and pagination behavior is retained; no endpoint, database or hosting-rule change is introduced.

- **Schema Read Metadata Cache**: Reuses a shared five-minute cache for the optional author display-name column instead of repeating its database metadata query on every uncached read. Cached decisions are installation/code-bound and discarded by install, Database Repair, SQL restore and managed update activation. Missing, expired or unusable cache storage falls back to the existing live check; failed database probes are never cached. Article data, public response caching, view counters and access rules are unchanged.

- **Settings Visibility Guidance**: Settings distinguish public site information from protected credentials. Profile and ad-code notices explain that saved values can be read in public site data even when a widget or ad slot is not displayed. Google integration guidance distinguishes public identifiers from private API keys, and the Gemini key field explains masked readback and browser visibility of newly entered values. No settings values, save behavior, permissions or secret-handling rules are changed.

- **Compatible Dependency Maintenance**: Updates OpenRouter SDK to 1.5.57, the TipTap family to 3.33.0, Tailwind CSS and its PostCSS plugin to 4.3.4, Lucide React to 1.69.0, Vite to 8.3.6, and the Node helper's express-rate-limit to 8.7.3. Production PHP requirements and stored settings are unchanged.

- **Related Posts Candidate Reliability**: Local article lists must cover the current category before replacing the bounded public candidate fetch. A failed candidate request no longer discards a successful companion response; when all requests fail, already available published candidates remain usable without overriding an authoritative empty response. Homepage hydration retains view counters for Most Viewed ordering, and missing counters trigger the existing public fetch. Candidate limits, sorting options, publishing permissions and stored plugin settings are unchanged; no archive-age quota is introduced.

- **Opt-in Hybrid Analytics**: Primary Admins can select Hybrid to record the existing Strict IP-window and Balanced browser-session measurements independently through the same tracking requests. Existing collection settings and history are retained; no browser cookie is silently enabled during upgrade. Cookie echo, consent, quotas and partial failures stay mode-aware, and reports remain separate rather than summing the two measurements. The Dashboard identifies configured collection, historical-only reports and empty/unavailable states, explains where to enable collection, and gives Primary Admins a read-only shortcut to the existing VonAnalytics settings panel. Existing analytics tables are reused; no new endpoint or table is introduced.

- **Atomic Strict Visit Reservation**: A bounded per-database, per-identity MySQL advisory lock serializes the Strict lookup and insert, preventing overlapping requests from recording the same initial window twice. The existing 30-minute and legacy-row rules are retained; locks are released on success, deduplication and write failure. Optional analytics cleanup cannot overwrite an accepted tracking acknowledgement.

Chart tooltip surfaces, labels, values and hover shading follow the Dashboard theme instead of retaining a near-white overlay in dark mode. Tracking, reporting queries, counts and stored settings are unchanged.

- **Version Alignment**: CMS package, lockfile and OTA metadata use 1.28.1. Installer, bundled theme and built-in plugin labels remain 1.28. ### [v1.28.0] - 2026-11-02

Uninstalling the selected theme switches to Default only after a successful settings save; Default remains available as a protected fallback. Reinstallation leaves the extension inactive until explicitly activated and restores its retained configuration. Confirmation and UI copy explicitly distinguish uninstall from resetting settings. Existing active theme selections take precedence over legacy uninstall markers. No bundled files, saved configuration or content are deleted; existing settings storage and permissions are unchanged.

- **AI Readiness After Settings Save**: Saving API settings synchronizes the editor's shared-key availability and effective model with the server acknowledgement, so a newly saved usable key does not require a page reload before generation. Clearing, expiry and unreadable-key states use the same safe projection as Settings reads. Provider keys remain server-side; permissions, encryption and quotas are unchanged.

- **Ad Layout Preservation**: Custom banner CSS that exceeds the direct-render style policy uses the existing opaque-origin iframe instead of losing positioning, decorative layers, spacing and text-overflow. Simple supported markup retains its sanitized direct path. This prevents MySQL error 2014 after the static-analysis cleanup while retaining row-by-row export and complete temporary-file generation before download. Backup permissions, source records and import behavior are unchanged.
- **Redirect and Profile Input Validation**: Redirect writes validate record IDs and field types before conversion or SQL, preventing malformed IDs from selecting another rule and compound URLs from causing a runtime error. Profile saves reject non-text bio values instead of storing `Array`. Existing Admin/CSRF/ownership checks, supported redirect methods and valid profile/password behavior are retained.
- **Registration Default Consistency**: Missing registration settings retain the enabled default already shown by Login and General Settings. Fresh installation stores that choice explicitly; an existing database OFF remains authoritative over the optional JSON mirror. Verification, CSRF, password rules and registration quotas are unchanged.
- **Thin Image Processing**: Main resizing and responsive variants keep a minimum one-pixel dimension instead of rounding valid thin images to zero. Unexpected processing errors return a bounded upload failure and remove only new files belonging to that upload before media registration. Existing images are not rewritten.
- **Focused Editor and Monitor Corrections**: Autosave reads the latest committed save callback without restarting its timer. Media metadata drafts remain bound to the open image, survive successful saves and retain newer typing. Queued Security refreshes retain the complete current page and filters instead of inheriting an older request's query. The optional local Node helper refuses unreadable or malformed existing content/user JSON before writing; missing stores retain initialization support. Existing publishing permissions and the deployed PHP data format are unchanged.
- **React Effect Ownership**: TechPress retains the same header DOM across parent renders instead of declaring a new nested component. Effects use their actual reactive fields or committed event callbacks, preserving manual searches, request cancellation, draft/route-entry lifetimes and Calendar focus behavior. Ad cleanup removes only its own frame. Related-post matching retains memoized random order through unrelated renders while refreshing changed card inputs. No endpoint, database or authentication rule is changed.
- **Development Quality Tools**: Added locked ESLint and development-only PHPStan tooling, read-only formatting/BOM commands and explicit CI checks. PHPStan covers all API and core modules plus shared security middleware at Level 9, targeting PHP 8.2, without a diagnostic baseline. Runtime boundaries validate database results, request field types and saved import checkpoints instead of assuming their shape; failed database-name reads stop before acquiring content/schema locks. Client contracts name the existing editor, Settings, theme, plugin and PHP-response shapes instead of broad explicit `any` annotations. Legacy wire aliases and stored widget compatibility remain available. React dependency warnings remain visible for ownership review; no production dependency on Composer or Node is introduced.

- **Profile Draft Concurrency**: Profile editors serialize pending saves and reconcile server-normalized fields without overwriting newer name, bio or avatar edits. A newer open draft stays editable after the earlier response; retry is available once the request settles. Corporate profile instances are keyed by identity so navigation does not reuse another profile's local editor state. Account permissions and password rules are unchanged.

The updater prepares and verifies a local deny-all shield before payload writes, refuses preparation failures and retains the shield until payload cleanup completes. Installer, Repair and Integrity recognize the same rule; Nginx parity and old-updater transition requirements are documented. Compact, authorized parent references keep older articles outside the loaded post list linkable without full article loads or per-comment requests. Missing, draft and future-publication parents remain non-clickable; public comment payloads and moderation actions are unchanged.

Editing your own account through User Manager refreshes the current profile and session presentation only after an accepted save, without changing authentication authority. Admin, profile and comment avatars share base-path-aware image loading, Gravatar fallback and retry after changing a failed URL. Public email privacy and avatar URL validation remain unchanged.
- **Settings Draft Preservation**: Late Settings reads and unrelated parent refreshes retain edited fields instead of replacing the open draft. Stale reads cannot overwrite newer refreshes or a Save/Cancel action. Failed saves retain the draft across optimistic rollback; successful saves preserve edits made while the request was pending and reconcile the returned credential projection. Cancel restores the latest accepted baseline. Existing Settings permissions, API endpoints and stored data are unchanged.

- **Analytics Counting Labels**: Dashboard cards explicitly identify the selected 7/30-day total, while chart legends and tooltips identify daily visits and daily unique IPs/browsers. A visible note explains why summed daily uniques differ from period-wide uniques. Tracking, deduplication, reports and stored data are unchanged.

- **WordPress Bridge Migration Corrections**: WXR fields are read independently of namespace prefixes. Password-protected Post/Page items become Drafts with a warning instead of losing their privacy boundary. Native excerpts/tags and supported Yoast/Rank Math descriptions use the existing editor fields, with visible length-limit warnings. Protected versioned key material retains the keys needed by the persisted credential during a file/database transition, including rollback or an uncertain commit; it is bounded rather than an unlimited key history. Missing/corrupt master material is not regenerated by Rotate. Status and last-rotation time are shown without exposing key bytes; back up the private file again after rotation. No schema change, paid provider request or personal-key storage is introduced.
- **Windows Storage and Import Cache**: Windows directory Read-only attributes no longer suppress limiter/cache writes when actual file I/O is allowed. Real file-open, lock and write failures retain their existing action-specific policies; Linux directory checks are unchanged. WordPress image localization and rollback invalidate staff storage totals immediately, including attachment-only batches. Reusing a localized URL now checks that its file still exists, so a later item can recreate an image removed by an earlier rollback. Existing articles and files are not rewritten in bulk.
